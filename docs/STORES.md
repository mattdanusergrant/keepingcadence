# App Store / Play Store plan — ready to trigger

The PWA (manifest + service worker + icons, shipped 2026-07) is the
foundation; the store apps wrap the exact same `app.html`. Nothing below
requires changing the product.

## Strategy: Capacitor wrappers

Wrap https://app.keepingcadence.com in [Capacitor](https://capacitorjs.com)
(one codebase, two native shells). Chosen over React Native/Flutter (no
rewrite) and over raw WebView wrappers (Capacitor gives maintained plugins:
status bar, splash, share sheet, app icons, deep links).

Repo layout when triggered:

```
native/
  capacitor.config.ts     # appId: com.keepingcadence.app, server.url -> prod
  ios/                    # generated by `npx cap add ios`
  android/                # generated by `npx cap add android`
```

Key config decisions (already made):
- **Remote URL mode** (`server.url: https://app.keepingcadence.com`): the
  native apps load production, so every web deploy updates both stores'
  apps instantly, no review cycle. Offline still works via the service worker.
- App ID `com.keepingcadence.app`; display name "Keeping Cadence";
  icons/splash generated from `icons/icon-512.png` + `maskable-512.png`
  via `@capacitor/assets`.
- Status bar tinted per theme (`ThemeDetection` + the app's
  `meta[name=theme-color]` already tracks the active palette).

## What the agent can do autonomously (≈1 session)

1. `native/` scaffold, both platforms, committed to the repo.
2. Android: full `./gradlew assembleRelease` build verification in CI or
   container (Java + Android SDK install is scriptable).
3. All store listing copy (EN + ES), privacy questionnaire answers
   (localStorage + optional Neon account sync; no ads, no tracking SDKs),
   screenshots at required sizes (Playwright, both languages, phone+tablet).
4. Signing docs: Android keystore generation commands; iOS provisioning
   walkthrough.
5. CI: GitHub Action for Android AAB on tag; Codemagic/EAS YAML for iOS.

## Human gates (Operator only — in order)

| # | Gate | Cost | Time |
|---|------|------|------|
| 1 | Google Play Console account | $25 once | ~1 day (ID verify) |
| 2 | Apple Developer Program | $99/yr | 1–2 days (ID verify) |
| 3 | Android keystore: run 1 command the agent provides, store the file + passwords somewhere safe (loss = can never update the app) | — | 5 min |
| 4 | iOS build service: connect repo to Codemagic (free tier OK) or any Mac with Xcode; agent supplies the YAML | — | ~30 min |
| 5 | Upload first builds + click "Submit for review" in both consoles (agent pre-fills everything it can) | — | ~1 hr |
| 6 | Test on your actual phones (TestFlight / Play internal track) before public release | — | your call |

## Risks / notes

- **Apple guideline 4.2 (minimum functionality):** thin web wrappers get
  rejected. Mitigations if it happens: add 2–3 native touches via Capacitor
  plugins (haptics on day-tap, native share sheet for schedule links, local
  notifications for shift reminders — the notification one is genuinely
  useful and the agent can build it).
- Play Store is far more permissive; expect Android to sail through first.
- The PWA remains the zero-friction path meanwhile: Share -> Add to Home
  Screen (iOS Safari) / Install app (Android Chrome).

**Trigger phrase:** "go stores" — the agent starts at step 1 of the
autonomous list and stops at each human gate with exact instructions.
